Django Deployment Overview

Django is a high-level Python web framework that enables rapid development of secure and maintainable websites. However, deploying Django applications to production requires careful consideration of several factors.

Unlike the development server (manage.py runserver), which is not suitable for production, a production deployment requires:

  • A dedicated web server (like Nginx or Apache)
  • An application server (like Gunicorn or uWSGI for WSGI, or Daphne for ASGI)
  • Proper configuration for static and media files
  • Environment-specific settings
  • Security considerations (HTTPS, secret key management, etc.)

WSGI Deployment

WSGI (Web Server Gateway Interface) is the traditional Python standard for synchronous web applications. Most Django deployments use WSGI.

Using Gunicorn

Gunicorn (Green Unicorn) is a popular WSGI HTTP Server for UNIX.

# Install Gunicorn
pip install gunicorn

# Run your Django project with Gunicorn
gunicorn myproject.wsgi:application

# With specific settings and workers
gunicorn myproject.wsgi:application --bind 0.0.0.0:8000 --workers 3 --env DJANGO_SETTINGS_MODULE=myproject.settings.production

Using uWSGI

uWSGI is a full stack for building hosting services, known for its performance.

# Install uWSGI
pip install uwsgi

# Run with uWSGI
uwsgi --http :8000 --module myproject.wsgi --master --processes 4 --threads 2

Example Nginx Configuration

Nginx is often used as a reverse proxy in front of WSGI servers.

# /etc/nginx/sites-available/myproject
server {
    listen 80;
    server_name yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /static/ {
        alias /path/to/your/static/files/;
        expires 30d;
    }

    location /media/ {
        alias /path/to/your/media/files/;
        expires 30d;
    }
}

ASGI Deployment

ASGI (Asynchronous Server Gateway Interface) is the emerging standard for asynchronous Python web applications and supports WebSockets.

Using Daphne

Daphne is a HTTP, HTTP2 and WebSocket protocol server for ASGI.

# Install Daphne
pip install daphne

# Run with Daphne
daphne -b 0.0.0.0 -p 8000 myproject.asgi:application

Using Uvicorn with Gunicorn

Uvicorn is a lightning-fast ASGI server implementation, using uvloop and httptools.

# Install Uvicorn and Gunicorn
pip install uvicorn gunicorn

# Run with Gunicorn and Uvicorn workers
gunicorn myproject.asgi:application -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000

Example ASGI Application

Ensure your project has an asgi.py file configured correctly.

# myproject/asgi.py
import os
from django.core.asgi import get_asgi_application
from channels.routing import ProtocolTypeRouter, URLRouter
from channels.auth import AuthMiddlewareStack
import myapp.routing

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')

application = ProtocolTypeRouter({
    "http": get_asgi_application(),
    "websocket": AuthMiddlewareStack(
        URLRouter(
            myapp.routing.websocket_urlpatterns
        )
    ),
})

Deployment Checklist

Before deploying your Django application to production, run through this checklist to ensure your configuration is secure and optimized.

Security Settings

  • Set DEBUG = False
  • Set a unique SECRET_KEY
  • Configure ALLOWED_HOSTS properly
  • Use HTTPS and redirect HTTP to HTTPS
  • Set secure cookie settings

Performance

  • Set up caching
  • Configure database connection pooling
  • Compress static files
  • Optimize database queries
  • Use a CDN for static files

Monitoring

  • Set up error reporting
  • Configure logging
  • Monitor performance metrics
  • Set up health checks
  • Implement backup strategy

Run Deployment Checks

Django includes a system check framework specifically for deployment:

python manage.py check --deploy

This command will check your settings for common deployment issues and provide recommendations.
